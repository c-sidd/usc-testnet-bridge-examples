# 05 — Scope and Requirements

## MVP goal

Build a testnet AI application that demonstrates a complete trust chain:

**source-chain event → attestation → proof generation → Creditcoin verification → verified fact → AI reasoning → policy check → bounded Creditcoin action.**

## Functional requirements

### FR-01 Source event
The source-chain contract must emit a dedicated, unambiguous event containing every value required by the Creditcoin-side application.

### FR-02 Event detection
The worker must discover new events and retain enough state to avoid silently losing work after a restart.

### FR-03 Attestation wait
The worker must not submit a readability query before the relevant source block is attested.

### FR-04 Proof generation
The worker must request the required Merkle and continuity proofs and preserve the source transaction hash, chain key, block height, and proof metadata.

### FR-05 On-chain verification
The ASC must synchronously verify the supplied proof through the Block Prover Precompile before accepting source-chain facts.

### FR-06 Verified fact
The application must create a deterministic fact object from verified transaction/event data. The AI layer receives this object, not arbitrary user text pretending to be blockchain state.

### FR-07 AI decision
The AI must return structured output such as `APPROVE`, `REVIEW`, or `REJECT`, together with a confidence/rationale summary and the exact verified facts used.

### FR-08 Policy enforcement
A deterministic policy layer must reject unsafe AI recommendations. AI output is never sufficient by itself to authorize arbitrary calldata.

### FR-09 Bounded execution
Only predefined smart-contract actions can be executed. The allowed action set, amount limits, asset, recipient rules, and expiry must be checked before execution.

### FR-10 Observability
The dashboard must show the complete lifecycle and current status for every request.

## Non-functional requirements

- **Deterministic on-chain rules:** critical authorization rules must be Solidity logic, not model output.
- **Idempotent worker:** restarting the worker must not intentionally create duplicate actions.
- **Auditable:** every decision should point to the source transaction and verified fact.
- **Testnet-first:** no production financial claims.
- **Small MVP:** prioritize one polished end-to-end path over many incomplete features.

## Explicit non-goals

- Autonomous unrestricted wallet control.
- Free-form smart-contract execution generated by an LLM.
- Treating an LLM response as proof.
- Real-money lending during the ideathon demo.
- Supporting many source chains before one chain works reliably.

## Acceptance criteria

The MVP is complete when a judge can watch one source-chain action progress to a verified Creditcoin-side action and inspect why the AI recommended it, while independently seeing that the underlying blockchain fact came through the Attestcoin verification path.
